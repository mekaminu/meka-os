# ADR-001: Cross-platform stack

**Status:** Accepted, 2026-10-01

## Context
MEKA OS must be first-class on a Samsung Fold (Android) and native-feeling on macOS, share correctness-critical logic (sync, merge, policy, planner, notification governor), work offline, and be maintained by one person with AI assistance. Animation quality matters.

## Options
| Option | Android / Fold | macOS quality | Native access | Shared logic | Cost for one person |
|---|---|---|---|---|---|
| Flutter | Good | Non-native feel | Platform channels for every hard feature (listener, alarms, Foundation Models) | Dart only | Low UI cost, high integration cost |
| Compose Multiplatform for both UIs | Excellent | JVM desktop app: large, non-native menus/windows, no direct Foundation Models access | Via interop | High | Lowest |
| Fully native, no sharing | Excellent | Excellent | Full | None: sync/policy/planner written twice | Highest, and two sources of truth for merge semantics |
| **KMP core + Jetpack Compose + SwiftUI** | Excellent | Excellent | Full | Domain, sync, policy, planner, governor | Medium |

## Decision
- **Kotlin Multiplatform shared core** (Kotlin 2.4.20) containing the domain model, life graph, sync engine, policy engine, planner, notification governor and AI provider interfaces.
- **Android UI:** Jetpack Compose (BOM 2026.09.00), `material3-adaptive` 1.3.0 and Jetpack WindowManager 1.5.1 for fold posture.
- **macOS UI:** SwiftUI. It consumes the core as an XCFramework with Swift-friendly APIs generated by SKIE 0.10.15, which supports Kotlin 2.4.20.
- **Backend:** Kotlin/Ktor 3.6.0 on the JVM, reusing the same core modules. The server materialises state with exactly the client's merge code.

## Consequences
- Two UI codebases. We accept this because Mac quality is a requirement and each UI stays thin: presentation state only, no business rules.
- The Kotlin/Swift boundary must stay small and stable. The core exposes a facade (`MekaCore`) with flows and suspend functions. SKIE maps these to `AsyncSequence` and `async`.
- Kotlin, SKIE and Xcode versions must move together. SKIE releases lag Kotlin by weeks, so we pin Kotlin to what SKIE supports.

## Revisit if
- The SwiftUI layer grows beyond about 25% of total UI effort, in which case we evaluate Compose Multiplatform for macOS again.
- SKIE stops tracking Kotlin releases.
